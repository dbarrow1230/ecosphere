# Gardening journal data-display audit

Completed October 31, 2026.

> Correction after the journal screenshot: the earlier route/API audit did not verify full content parity. It missed 60 records with capitalized `Notes`/`JournalDate`, and the journal was locked to the current month. Those issues were corrected in the follow-up below; the earlier broad completion claim was too strong.



## Verification

- Inventoried 76 route definitions and 179 reachable frontend source files.
- Checked SPA delivery for all 73 routes that do not need a record ID or password-reset token.
- Queried all 113 mounted API roots. No server errors remained. Some router roots correctly require a subpath, business ID, or user ID and return 400/404 without those arguments.
- Browser-rendered the library, planning, journal, growing, harvest, reference, vendor, public, and administration pages, plus a real garden detail page and redirects. Confirmed the vendor crashes were resolved and Brussels Sprouts shows Cabbage aphid, Cabbage looper, and Clubroot.
- Validated stored records against 14 principal Mongoose models without saving them.
- Fifteen focused regression tests passed. Production build passed.
- Read-only checks did not submit create/edit/delete forms, log in as another user, or exercise password-reset submission. User/profile/admin authorization screens need a signed-in session for those workflows.

## Corrections

- Map legacy seed, species, plant, task, vendor, and reference fields to current model fields.
- Restore legacy collections to the current collection names, retaining source collections and source IDs. Multiple growing cycles become separate model records; subsequent cycle IDs are generated by MongoDB and keyed by legacy instance/index for idempotency.
- Never overwrite current records or replace fields already present, including intentional blanks.
- Support combined and separate legacy pest/disease management entries and preserve their original treatments/prevention.
- Use harvestingInformation for harvest timing; display stored USDA-zone text and lifespan descriptions; convert known dimensions to the missing unit instead of printing invented zeros.
- Preserve journal note text and dates from strings, objects, or arrays, and handle old notes safely in the dashboard.
- Register missing population models on the correct connections, including equipment/ingredients, treatment types, pricing references, and permission-override users.
- Route browser document navigation to Vite while preserving upload-file proxying, including /vendors/seeds and /vendors/equipment.
- Render populated vendor location references as text rather than React child objects.
- Keep existing colors and CSS styling. No CSS was changed for this audit.

## Existing source-data gaps

- Fifty-nine legacy seed records lack the required `user` owner field. Their read displays work; ownership was not assigned by assumption. Saving these records requires a valid user supplied by the existing edit workflow.
- Older imports include literal `REPLACE_WITH_...ObjectId` placeholders and some dangling relationships. Placeholders remain in the legacy data and are excluded from populated reference fields; no IDs or relationships were invented.
- Empty source fields remain empty/Not listed. Several original image files are absent from the upload directory; missing originals were not replaced with unrelated pictures.
- Some older garden/bed records have no resolvable relationship to a current garden; they were not attached to an arbitrary garden. Imported gardens can therefore have no assigned sections or type.
- Stored taxonomy is displayed as recorded. This audit did not research or rewrite biological classifications.
